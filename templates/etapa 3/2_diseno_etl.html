2. Diseño del Paquete ETL (SSIS)

Arquitectura del proceso de extracción, transformación y carga (ETL) implementado en SQL Server Integration Services, aplicando las reglas de tratamiento definidas en la sección anterior. Se construyó un paquete .dtsx por cada archivo fuente, más un paquete maestro que los orquesta.

Control Flow (igual para los 6 paquetes)
Execute SQL Task — TRUNCATE staging_<archivo>
Garantiza staging limpio antes de cada corrida (clave para la prueba anti-duplicados)
Data Flow Task — Extracción → Staging
Data Flow Task — Transformación y limpieza
Data Flow Task — Carga a tablas finales (aceptados / a revisión / duplicados)
Data Flow (patrón general)
Source (Flat File / Excel Source)
OLE DB Destination → staging_<archivo>
Copia cruda intacta del dato original, sin transformar — trazabilidad total
Derived Column
TRIM/UPPER, reemplazo "SD"→NULL, corrección ANO/COD_MUN_O, reasignación CICLO DE VIDA/MES
Data Conversion
Tipos correctos (DT_I4, DT_DATE, etc.)
Lookup
Homologación categórica (régimen, nacionalidad) y geográfica (municipios/departamentos DANE)
Match
No Match → a revisión
Sort (Remove rows with duplicate sort values)
Deduplicación exacta de filas
Conditional Split
Reglas de validez/rango (edad 0-110, atípicos, nulos en campos clave)
tabla_aceptados
tabla_revision (+ motivo, + valor original)
Zona de Staging

Cada paquete carga primero una copia 1:1 del archivo original en una tabla de staging, sin ninguna transformación. Esto permite repetir el proceso, auditar qué había antes del tratamiento, y sirve de base para la prueba de no duplicación al reejecutar el mismo lote.

Prueba de Idempotencia

Antes de cada corrida, un Execute SQL Task trunca la tabla de staging (o se valida una clave de lote/hash). Esto garantiza que reejecutar el mismo archivo fuente no genera registros duplicados adicionales en las tablas finales.
